# ПОС — преподавательская оценка студентов

Консольное приложение для одного курса на C++20. Преподаватель добавляет студентов и критерии рубрикатора, выставляет и исправляет оценки, смотрит итоги и выгружает ведомость в CSV. Студенты, рубрикатор и оценки хранятся в памяти до завершения процесса. Выгруженный CSV остаётся на диске.

## Сборка и запуск в Ubuntu WSL

Нужны компилятор с поддержкой C++20 и CMake 3.20 или новее. Команды ниже выполняются из корня репозитория.

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
./build/pos
```

## Доменная модель

| Термин | Роль в коде |
| --- | --- |
| Студент | `Student` — сущность со стабильным ID. Имена студентов могут совпадать. |
| Рубрикатор и критерий | `Rubric` — агрегат критериев `Criterion`. Он обеспечивает уникальность ID критериев. У критерия есть имя, конечный положительный максимум и конечный положительный относительный вес. |
| Оценка | `Evaluation` — сущность с идентичностью по паре `(StudentId, CriterionId)`. Хранит проверенный балл `Score`, объект-значение без собственного ID. |
| Итог | `FinalResult` — снимок расчёта со статусом и, при полном наборе оценок, процентом. `FinalGradeService` вычисляет его по текущему рубрикатору. |

Студент и отдельная оценка имеют собственные границы хранения. Оценка ссылается на студента и критерий по ID. Сценарий приложения проверяет наличие студента, фабрика проверяет принадлежность критерия рубрикатору и диапазон балла `[0, max_score]`, а репозиторий оценок обеспечивает уникальность пары. Исправление подставляет новый проверенный балл в существующую запись. Отмена убирает запись.

Итог в процентах считается по формуле `100 × Σ(weight × score / max_score) / Σ(weight)`. Нормирование позволяет задавать веса, например, как `2` и `1`. Пустой рубрикатор и незаполненные оценки дают разные статусы. Отмена оценки или добавление нового критерия возвращают студента в статус ожидания оценок. В среднем по курсу участвуют только студенты с числовым итогом. В консоли и CSV итог отображается с двумя знаками после точки.

## Порты и адаптеры

- `pos_domain` (`src/domain.cpp`, `include/pos/domain.hpp`) содержит сущности, инварианты и расчёт.
- `pos_application` (`src/application.cpp`, `include/pos/application.hpp`) содержит фасад сценариев и выходные порты `StudentRepository`, `RubricRepository`, `EvaluationRepository`, `ResultsExporter`.
- `pos_adapters` (`src/console.cpp`, `src/adapters.cpp`) содержит консоль, репозитории в памяти и запись CSV.
- `src/main.cpp` — точка сборки. `DiContainer` хранит реализации под типами портов. `main` получает их из контейнера и передаёт в конструктор `PosFacade`. Консоль получает собранный фасад.

```text
Консоль ──────────────────────► Application ──► Domain
Репозитории и экспортёр ──────► Порты в Application
main ─────────────────────────► Application и адаптеры
```

| GoF | Где применяется | Зачем |
| --- | --- | --- |
| Фабрика | `EvaluationFactory` в Domain | Выставление и исправление используют одни правила создания оценки и проверки её связи с рубрикатором. |
| Facade | `PosFacade` в Application | Консоль вызывает операции курса через один интерфейс. Фасад координирует доменную модель и выходные порты. |
| Command | `Command` в консольном адаптере | Каждому пункту соответствует исполняемое действие. Цикл меню выбирает его по номеру, а чтение параметров и вызов фасада выполняет команда. |

## Сквозная демонстрация

Обычное меню принимает команды с клавиатуры или из стандартного ввода. Следующий прогон создаёт двух студентов и два критерия, заполняет ведомость для первой студентки, показывает её итог и сводку, затем экспортирует результаты обеих строк.

```bash
demo_dir=$(mktemp -d)
./build/pos <<EOF
1
Анна, "группа 1"
1
Борис
3
Практика
10
2
3
Экзамен
20
1
5
1
1
8
5
1
2
10
9
1
10
11
$demo_dir/itog.csv
0
EOF
cat "$demo_dir/itog.csv"
```

Итог Анны равен `70.00%`. Числовой итог есть у одного студента из двух, средний итог также равен `70.00%`. У Бориса поле процента пустое.

```csv
student_id,student_name,status,final_percent
1,"Анна, ""группа 1""",complete,70.00
2,Борис,missing_evaluations,
```

Статус `empty_rubric` означает, что критериев пока нет. Экспорт создаёт файл в существующей папке. При повторном экспорте по тому же пути готовая ведомость заменяет предыдущую.
